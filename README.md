I build small, verification-first tools for open-source documentation and agent workflows.

## README Makeover Toolchain

Tools for turning a technically capable but hard-to-use GitHub README into a fact-checked, maintainer-friendly proposal.

- [GitHub README Makeover Skill](https://github.com/lukatong/github-readme-makeover-skill): audits first-run paths, information architecture, screenshots, and verified sponsorship wording.
- [README Fact Checker](https://github.com/lukatong/readme-fact-checker): checks local README links, images, code fences, setup signals, and funding configuration.
- [Open Source Screenshot Planner](https://github.com/lukatong/open-source-screenshot-planner): plans real product screenshots, capture states, redaction, placement, and alt text.
- [README Evidence Report](https://github.com/lukatong/readme-evidence-report): creates evidence reports for Issues and pull requests.
- [README Freshness Checker](https://github.com/lukatong/readme-freshness-checker): detects when an audit revision no longer matches the upstream README.
- [README PR Composer](https://github.com/lukatong/readme-pr-composer): drafts conservative README-only PR text after explicit maintainer approval.
- [README Makeover Case Tracker](https://github.com/lukatong/readme-makeover-case-tracker): records public proposals, maintainer feedback, and outcomes with linked evidence.

**Need an audit for a public repository?** Open a [README audit request](https://github.com/lukatong/github-readme-makeover-skill/issues/new?template=readme-audit-request.yml).

## Working Principles

- Verify repository facts before rewriting documentation.
- Prefer narrow, reviewable README changes over broad visual rewrites.
- Do not treat a public case study as maintainer endorsement.
- Keep secrets, private URLs, customer data, and unpublished security details out of public requests.
